# Core Platform Implementation Plan (Next.js on Vercel)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Next.js app at `web/` deployed on Vercel that hosts a launcher, four app route groups, a shared UI kit, a polling-based realtime room layer with pluggable storage, a model layer with visible attribution, and a bump-pairing endpoint, so four app agents can build in parallel.

**Architecture:** Next.js 15 App Router (TypeScript, Tailwind v4). Backend = route handlers under `app/api/*` (Vercel functions). Rooms = versioned JSON state in a store (`memory` locally, `upstash` REST when `UPSTASH_REDIS_REST_URL/TOKEN` exist), read by clients through 800 ms polling with ETag-style version checks, written through `POST /api/rooms/{app}/{code}/act` which runs the app's reducer server-side. LLM calls run server-side through one `llm.json()` with `ifm | compatible | mock` providers; every call emits an observability event stored per room so stage views can render the model ladder. HTTPS on Vercel unlocks DeviceMotion (bump) and geolocation on iOS.

**Tech Stack:** Node 25, pnpm 11, Next.js 15 (App Router, Turbopack dev), React 19, TypeScript 5, Tailwind v4 (`@tailwindcss/postcss`), zod, qrcode, `@upstash/redis`, vitest, Vercel CLI 58 (logged in as `joaobarbosa`).

**Spec:** `docs/superpowers/specs/2026-09-12-core-design.md` (the spec's WebSocket section is superseded by polling; everything else holds). Visual contract: `docs/mockups/index.html` (open it in a browser before writing UI).

export async function getRoom(app:AppName, code:string):Promise<RoomDoc|null>;
